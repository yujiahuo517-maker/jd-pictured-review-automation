# 稳定性说明

## 为什么弃用旧线下链路

旧版本在 2026-09-15 和 2026-09-16 连续失败于 EasyBI 页面元素定位：`找不到带图评价明细表`。该链路还依赖 WebCLI 扩展、页面内 Vue 实例、固定表格列位置、DesignSpark 页面、Excel 文件锁和长时间运行的 pyz。任一页面升级、登录态变化或进程残留都会让整日任务中断。

本 Skill 改用 EasyBI 直连接口锁定业务范围，再使用 Blacklight 的 OSW 带图评价接口链路：

`userinfo → easybi_pic_pending → targets(spu_ids) → llm_image → imgzone_upload/find → ai_text → screen → import_dryrun → import → tasks/task_stats`

EasyBI 使用看板元数据和查询接口，不依赖 DOM、Vue 实例或固定列位置；返回结果会校验日期、ERP 和“是否带图评价标识=否”。它把“页面是否长得一样”改成“接口返回是否满足契约”，并用提交前后二次查询实现幂等。

## 范围保护

- 用户给出的 SKU/SPU 是硬边界，任何阶段都不得扩展到边界之外。
- 没有显式 SKU/SPU 时，必须先从 EasyBI 查询销售员 ERP 名下未完成 SPU，并把结果作为 OSW 硬范围。
- EasyBI 查询失败或返回字段不符合契约时停止，不得退化为无范围 `osw_pic_targets`；后者口径可能覆盖远超当前销售员名下的商品。
- 不再用本地“7 天完成历史”判断是否完成。平台待补清单和任务状态才是事实源。

## 幂等键

把以下组合视为一次逻辑任务：

`ERP + SKU + 图片文件名 + 当日日期`

恢复时按顺序检查：

1. `osw_pic_tasks` 是否已有任务；有则只回读。
2. `osw_pic_targets` 是否仍待补；不在则不再提交。
3. `osw_pic_imgzone_find` 是否已有同名图；有则复用 URL。
4. 只有三者都未命中时才重新生成。

## 真实评价图文闸门

- 真实评价行必须标记 `source_type=real_review`，且所有图片均为京东晒单 `/shaidan/` 地址。
- 拒绝真伪、品牌、宣传一致性质疑，以及“否定 + 正面词”的委婉负面表达。
- 明确品牌背书与目标商品标题不一致时转人工复核，不允许自动提交。
- 同一评价内、同一批次内不得重复使用图片；提交前历史图片索引默认扩展到平台可访问的最近 20000 条。
- 机审报“已经被使用过”时，把该 URL/CRC 记入去重库，重新采集不同评价的整组图文，不复用原图或原文。

## 状态解释

- `330`：生效，唯一最终成功态。
- `1`、`3`、`6`、`10`、`210`、`310`：尚未最终生效，保留并继续回读。
- `4`：机审拒绝，记录逐图或任务拒因，勿原样重提。
- `11`：已有评价，按已完成处理，不再提交。
- `13`：同步失败，先回读详情，再决定是否人工处理。
- `20`、`220`、`320`：创建失败，修正明确原因后才能重试。

## 运行建议

- 日常小批量默认 10 条；确认稳定后也不要超过 Blacklight 单批上限 200。
- 生图、上传、AI 文案和提交全部串行，避免网关限流和同 SKU 槽位竞争。
- 长等待不占用会话：首次回读仍处理中时，报告待回读清单；下一次从任务回读开始。
- 不删除图片空间中的已上传图片。删除不可恢复，且可能破坏已生效评价。
